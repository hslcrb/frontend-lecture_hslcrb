# Blue Renaissance CMS · 비밀번호 화면과 서버 저장 원칙

2026-11-09 업데이트.

## 사용자에게 보이는 화면

관리자 로그인 화면은 기술 구현을 설명하는 장소가 아닙니다. 사용자는 필요한 작업에만 집중할 수 있도록 구성합니다.

- 최초 방문: **비밀번호 설정** / 비밀번호 / 비밀번호 확인 / 비밀번호 설정 버튼.
- 다음 방문: **관리자 로그인** / 비밀번호 / 로그인 버튼 / **비밀번호 찾기**.
- 비밀번호 찾기: **재설정 메일 보내기** → 본인 이메일의 일회용 링크 → **새 비밀번호 설정**.
- Google Access는 화면 진입 전에 계정을 확인합니다. 별도 화면에 JWT, PBKDF2, D1, 서버 암호화, 재배포 및 기술구현 설명을 표시하지 않습니다.
- 최소 비밀번호 길이 등 검증 제약은 폼에서 처리하고, 잘못 입력한 경우에만 간단한 오류 안내를 표시합니다.

## 실제 저장 방식

- 로그인 주체와 역할은 Google Access의 검증된 이메일/subject 및 D1 관리자 권한 목록으로 판별합니다.
- 관리자 비밀번호의 **서버 보관용 검증값, 개별 솔트, 반복 횟수, 인증방식 버전, 실패 횟수**는 D1 `lab_teacher_credentials`에 지속 저장됩니다.
- 로그인 세션 원문은 HttpOnly 쿠키로 전달하고, D1 `lab_teacher_sessions`에는 세션의 해시와 만료 시간이 저장됩니다.
- 비밀번호 재설정용 1회 토큰의 해시·유효기간·사용 이력은 D1 `lab_teacher_reset_tokens`에 저장합니다.
- 학생 이름, 계정 고유 ID, 점수 및 학습 기록, 강의 본문, CMS 초안/게시본과 복원 이력도 D1에 저장됩니다. React·CSS·JS·SVG 등 정적 실행 파일은 Cloudflare Workers Assets로 서버에 배포합니다.
- 비밀번호 원문을 복원 가능한 형태로 서버에 저장하지 않습니다. **비밀번호 찾기**는 인증된 메일로 새 비밀번호를 만드는 절차이지 원래 비밀번호를 회수하는 기능이 아닙니다.
- 서버의 `AUTH_PEPPER`는 GitHub에 공개하지 않고 Cloudflare Worker Secret으로 보관합니다.

## 복구 메일 활성화 조건

Cloudflare에서 관리자 계정의 Email Routing 수신 주소가 검증되어야 실제 복구 메일이 전달됩니다. 최종 조회 당시 창조자와 선생님 주소는 모두 `unverified`였으며, 해당 계정 소유자가 Cloudflare 인증 메일을 확인해야 합니다. 이 인증 전에는 복구가 정상 동작한다고 안내하지 않습니다.

비밀번호 자체·실제 보관 검증값·재설정 토큰·쿠키·서버 비밀키는 개발 문서나 로그에 기재하지 않습니다.
